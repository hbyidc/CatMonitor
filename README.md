# CatMonitor 监控系统

基于 PHP 的服务器与网站监控系统，集成多协议探测、资源采集、公开状态页、历史趋势、告警通知和开放 API。后台使用 Light-Year Admin V5、Bootstrap 5 与 jQuery，支持 SQLite 和 MySQL。

## 功能概览

### 多种探测方式

| 类型 | 功能说明 |
| --- | --- |
| PING | ICMP 连通性、延迟和丢包率检测；优先使用 PHP Sockets，条件不足时尝试系统 `ping` |
| TCP | 检查指定 TCP 端口的连通性与连接延迟 |
| UDP | 发送探测包，根据响应、端口拒绝或超时判断状态 |
| SSH | 检查 SSH 服务；配置账号密码并安装 `ssh2` 扩展后支持登录验证与资源采集 |
| SSH + PING | 同时检测 SSH 与 PING，任一通道可达即判定在线，分别记录相应延迟 |
| HTTP(S) | 网站状态码、响应延迟检测，以及 HTTPS 证书剩余天数检测 |
| 宝塔面板 | 通过面板 API 检测状态，并可采集服务器资源数据 |

> UDP 无连接，当前实现把“超时但未收到拒绝响应”视为可达，不能据此保证业务服务正常。SSH 未安装 `ssh2` 扩展时仅检测 SSH Banner，不会执行登录验证或资源采集。

### 节点管理与公开状态页

- 节点新增、编辑、删除、备注、检测间隔与超时设置。
- 节点分类管理，监控总览支持分类和节点拖动排序。
- 列表内快速切换监控、资源采集及前台显示状态。
- 手动探测单个节点、全部启用节点，快速采集结果弹窗。
- 前台按分类展示节点状态、延迟、可用率和故障提示，每分钟自动刷新已保存的数据。
- 支持隐藏节点或分类，配置前台资源与历史展示、站点名称、Logo、图标和备案信息。

### 资源监控与历史分析

- SSH / SSH + PING / 宝塔节点支持 CPU、内存、磁盘、负载和上下行带宽采集。
- SSH 资源采集面向 Linux，通过远程命令读取 `/proc` 与文件系统信息，无需在目标服务器安装专用 Agent。
- 支持多磁盘占用展示；服务器列表优先显示系统盘及占用率最高的两个数据盘。
- 可按节点启用长期监控，保留最近 **1 / 3 / 7 / 30 天**的资源历史。
- 性能趋势页展示资源与带宽曲线，并支持时间范围切换和图表缩放。
- 网络质量页提供延迟、丢包、可用率统计和最近 50 次探测记录。
- 可用率与健康状态支持阈值、评分参数配置；评分结果不等同于严格的业务 SLA。
- 探测日志支持查询，计划任务负责清理过期探测日志。

### 预警通知

支持以下触发条件：

- **离线预警**：连续检测失败达到配置次数。
- **SSL 预警**：证书即将到期或已经过期。
- **资源预警**：CPU、内存或任一已采集磁盘超过阈值；磁盘告警包含挂载点。

通知渠道：

| 渠道 | 说明 |
| --- | --- |
| SMTP 邮件 | 支持 SSL、STARTTLS 和普通 SMTP 配置 |
| Webhook | POST JSON，可配置校验 Token |
| 短信 | 短信宝、腾讯云短信、阿里云短信，选择其中一种接口使用 |
| Telegram | 配置 Bot Token 和接收目标 |

支持渠道测试、按节点与告警类型限制发送频率、设置通知时间窗口（含跨天时段），并记录发送结果。

### 开放 API 与 SSO

开放 API 使用 `api_id` + `api_key` 鉴权，提供监控总览、主动探测、性能趋势、网络质量和告警查询。后台有独立的 **API 文档**页面。

SSO 采用两步式流程：服务端使用 API 凭证换取短期登录 token，再通过返回的登录地址进入后台。可在系统设置中控制临时令牌登录开关。

### 在线更新

- 授权查询、授权验证、检查版本及逐版本升级。
- 实时显示升级步骤和失败详情。
- 更新请求及下载强制 HTTPS，校验证书信任链和域名。
- 授权码保存在数据库中，不使用 `license.dat`。
- 更新时排除本地配置、运行数据、上传文件、`.user.ini` 和 `license.dat`。
- 授权或网络异常只影响在线升级，不影响监控和后台日常使用。

> 更新前必须独立备份数据库与站点文件。当前更新器会备份被覆盖的原文件并尝试恢复，但不保证失败后恢复所有数据库变更及新增文件，不能替代完整备份。

## 运行环境

推荐使用 Linux + Nginx + PHP-FPM，可通过宝塔面板部署。

| 项目 | 要求或用途 |
| --- | --- |
| PHP | 8.0 及以上；V0.1.0 发布验证使用 PHP 8.1 |
| 数据库 | SQLite 或 MySQL，安装对应的 `pdo_sqlite` / `pdo_mysql` 扩展 |
| 基础扩展 | `PDO`、`curl`、`mbstring` |
| GD | 登录图形验证码需要 |
| OpenSSL | 证书检测、加密通信及相关通知能力需要 |
| Sockets | PHP 原生 ICMP PING；仍需系统允许相应 Socket 操作 |
| SSH2 | SSH 登录验证与资源采集需要 |
| Zip | 在线更新需要 |
| `exec` 与系统 `ping` | PING 降级或相关 IPv6 探测场景按需启用 |
| 网络 | 监控主机需要能够访问目标节点、通知服务及授权更新服务 |

前端静态资源已包含在源码中，部署无需运行 npm 构建。

## 安装与部署

### 1. 下载程序

从 [V0.1.0 Release](https://github.com/hbyidc/-CatMonitor/releases/tag/v0.1.0) 下载 `CatMonitor-V0.1.0.zip`，解压到站点根目录。

Release 同时提供 `SHA256SUMS.txt`，可在下载目录校验：

```bash
sha256sum -c SHA256SUMS.txt
```

目录层级应为 `站点根目录/index.php` 与 `站点根目录/admin/install.php`，不要只上传 `admin` 目录。

### 2. 配置站点与权限

1. 设置 PHP 版本，安装所需扩展，为站点配置 HTTPS。
2. 安装期间确保 Web 运行用户能够写入 `admin/` 和 `admin/data/`，用于生成配置及数据库。
3. 使用品牌图片上传时，确保 `uploads/` 可写；使用在线更新时，Web 用户还需有目标程序文件与目录的写入权限。
4. 计划任务尽量使用与 Web 服务相同的运行用户，避免生成只有 root 可写的锁文件或临时目录；不要用 `777` 代替正确的用户与权限配置。

### 3. 保护运行数据

**首次安装前**，在 Nginx 站点的 `server` 配置块中加入以下规则，并验证配置后重新加载：

```nginx
# 禁止通过 HTTP 下载数据库、日志、备份和临时更新包。
location ^~ /admin/data/ {
    return 404;
}

# 配置仅由 PHP 本地加载，不需要直接访问。
location = /admin/config.php {
    return 404;
}

# 防止 Git 元数据暴露。
location ^~ /.git/ {
    return 404;
}
```

以上示例适用于部署在域名根目录的站点；子目录部署需调整路径。其他 Web 服务器需配置等效访问限制。目录中的 `index.html` 只用于占位，不能防止已知文件路径被直接下载。

### 4. 运行安装向导

访问：

```text
https://你的域名/admin/install.php
```

按向导完成：**环境检查 → 数据库配置 → 管理员账号 → 安装完成**。

- SQLite：无需单独创建数据库服务，数据文件位于 `admin/data/`。
- MySQL：先创建数据库及专用账号，再在向导中填写连接信息。
- `admin/config.php` 由向导生成；分发包不包含生产配置，也没有预置管理员密码。
- 系统未完成安装时，前后台入口会引导进入安装流程；已安装时再访问向导会显示安装完成。

常用入口：

| 页面 | 路径 |
| --- | --- |
| 公开状态页 | `/` |
| 后台登录 | `/admin/login.php` |
| 安装向导 | `/admin/install.php` |
| API 文档 | `/admin/api_doc.php`（需登录） |

### 5. 配置定时任务

推荐每分钟执行一次，以下两种方式任选其一。

**命令行方式**：

```bash
/www/server/php/81/bin/php /www/wwwroot/你的站点目录/admin/cron/probe.php
```

宝塔面板中选择“计划任务 → Shell 脚本”，周期设为每分钟；`81` 和站点目录需按实际环境修改。CLI PHP 与站点 PHP 应具备一致的扩展。

**访问 URL 方式**：

登录后台，在“系统设置”的计划任务区域复制带密钥的触发地址，交给定时任务访问。该密钥应保密，泄露后可在后台重新生成。

两种计划任务入口共用文件锁，上一轮未结束时会跳过新任务。每轮按节点配置判断是否到达检测时间；实际采样频率还受任务调度周期和探测耗时影响。节点设为 10 秒、计划任务每分钟执行，并不等于每 10 秒采集一次。

> 前台页面自动刷新只读取已有数据，不代替定时探测。节点较多时，顺序探测一轮可能超过一分钟，应结合超时、间隔及资源采集开关调整配置。

### 6. 添加节点与通知渠道

1. 在“节点分类”创建分类，在“服务器管理”添加目标节点。
2. SSH 资源监控需配置可登录的账号密码，并开启资源采集；需要趋势图时再启用长期监控。
3. 宝塔节点需在目标面板开启 API、获取接口密钥，并将监控主机 IP 加入允许列表。
4. 在“系统设置”配置预警规则和通知方式，保存后执行渠道测试。
5. 根据展示需求设置前台隐藏、资源展示和历史展示选项。

## API 接入

入口：`/admin/api/open.php`。凭证在后台“系统设置 → 开放 API”中查看、重新生成或停用。推荐由可信服务端使用请求头传递凭证，不要将密钥写入公开网页。

```bash
curl 'https://你的域名/admin/api/open.php?action=overview' \
  -H 'X-Api-Id: 你的_API_ID' \
  -H 'X-Api-Key: 你的_API_KEY'
```

| `action` | 用途 | 主要参数 |
| --- | --- | --- |
| `overview` | 获取分类及节点总览，不触发探测 | `include_hidden`、`with_resource`、`with_history` |
| `probe` | 立即探测指定节点，会写入结果 | `server_id` |
| `probe_all` | 立即探测全部启用节点，会写入结果 | 无 |
| `trend` | 查询 SSH / 宝塔类节点的资源趋势 | `server_id`、`range` |
| `quality` | 查询延迟、丢包与可用率历史 | `server_id`、`range` |
| `alerts` | 查询预警记录 | `type`、`server_id`、`since`、`limit`、`page` |
| `alert_config` | 查询预警阈值及渠道开关，不返回渠道凭证 | 无 |
| `token` | 换取 SSO 短期登录 token | `ttl` |

SSO 推荐使用 POST 换取 token，默认有效期 120 秒，可配置范围为 30～600 秒；取得响应中的 `login_url` 后再跳转登录。详细字段及示例见后台 API 文档。

**权限提示：** API 凭证可以触发探测；开启 SSO 时还可换取主管理员登录身份，并非只读凭证。避免高频调用 `probe` / `probe_all`，展示大屏优先定时读取 `overview`，不要在每次页面刷新时触发全量探测。

## 部署注意事项

- 后台写请求已接入 CSRF 防护，但仍应设置强密码，并结合反向代理限速、IP 白名单等方式保护管理入口。
- 全站使用 HTTPS；生产环境应关闭 `admin/bootstrap.php` 中的 `display_errors`，将错误写入受保护的日志。
- 数据库中保存用于采集和通知的敏感信息，包括 SSH 密码、面板密钥、API 凭证等。限制数据库账号权限，保护数据库和备份，勿将其提交到 GitHub。
- 不使用 SSO 时关闭对应开关；不要把高权限 API 凭证交给不可信第三方。
- 仅上传可信品牌图片；对外部署需配合上传目录的脚本执行限制和文件类型策略。
- 在线更新的证书校验不代表所有第三方采集与通知接口都采用相同策略；面板采集及通知连接需根据当前实现与部署网络单独评估。
- 更新前确认来源可信，并完成文件和数据库备份。证书错误应通过修复 HTTPS / CA 配置解决，不应关闭更新器校验。
- 安装完成后可在 Web 服务器上限制安装入口访问。不要为重新进入向导而直接移除生产配置或数据库。
